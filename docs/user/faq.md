# 常见问题

## 电脑睡眠时会跑吗？

不会。睡眠和关机期间不会发出任何调用，e5extend 也**不补跑**错过的轮次。唤醒后它会检测到时间跳跃，
等 1 到 3 分钟（让网络恢复）再继续。重新启动 e5extend 时如果某个账号的下一轮已经错过很久，只会在几分钟内（带随机抖动）补跑**一轮**，
日志里有一条 `catch_up`，不会把错过的轮次连着补完。想要持续有活动，请用常开的机器或服务器。

## 关机多久会出问题？

两方面：

- **开发者订阅是否续期**：微软没有公开标准，无法给出确切的天数。`doctor` 在 72 小时没有成功调用时警告，7 天时报失败。
- **登录会过期**：委托身份的刷新令牌闲置 90 天后失效（每次使用会顺延）。停机超过 90 天就要重新 `account login`。

## 令牌过期怎么办？

访问令牌（约 1 小时）由程序自动刷新，你不用管。如果刷新失败，账号会进入 `needs_attention` 状态并发告警，
原因里带着下一步命令，通常是 `e5extend account login <名称>`。client_secret 的密钥有固定到期日，
记得用 `--secret-expires` 登记，到期前会提醒；换新密钥用 `e5extend account set-secret`。
修好之后 `e5extend account resume <名称>` 可以立刻恢复。

## 后台运行一段时间后要求重新登录（条件访问的登录频率）

现象：账号每隔一两个小时就进入 `needs_attention`，原因里有 `AADSTS70043`，重新登录后又能用几个小时。
这是租户里的条件访问策略设了“登录频率”（sign-in frequency），把用户的刷新令牌限制在几个小时内；
只要后台还在用这个用户身份取令牌，就会被周期性踢下线。不是程序的问题，也不是令牌被撤销。

三种登录方式面对这条策略的表现不同：

| 方式 | 结果 |
| --- | --- |
| 委托身份（设备码、浏览器） | 受策略限制，到点就要人重新登录。 |
| 账号密码 | 刷新令牌被拒时，后台引擎会用本机加密保存的密码自动重新登录，不用人。但只适用于没有 MFA 的账号；E5 开发者租户通常通过安全默认值强制 MFA，而设了登录频率策略的租户往往也同时要求 MFA，所以这条路多半走不通。密码出错、需要 MFA 或被策略拦截后，程序不会再重复尝试（避免锁号），要用 `account set-secret` 或 `account login` 才会恢复；两次自动登录之间至少隔 30 分钟。 |
| 应用身份（Client Secret） | 不是用户登录，不受用户登录频率策略影响，适合长期后台运行。 |

建议按顺序处理：

1. **改用应用身份**：`e5extend account add <名称>-app --auto --auth client_secret`（桌面版里账号卡片上有“改用应用身份”按钮）。
   应用身份读取的是一个指定用户的数据，需要给出该用户的邮箱（UPN）；Client Secret 会过期，记得登记到期日。
2. 账号确实没有 MFA 的话，才考虑账号密码方式（`--auth password`）。密码加密保存在本机，不会写进日志。登录频率策略常和 MFA 一起出现，所以优先用第 1 种。
3. 或者请租户管理员在条件访问策略里排除本应用注册，然后 `e5extend account login <名称>`。

## 怎么确认它真的在工作？

```bash
e5extend status          # 每个账号的“上次成功”和今天的成功/失败次数
e5extend logs -f         # 实时查看调用记录
e5extend doctor          # 全面检查
```

数据目录里还有 `heartbeat` 文件，引擎每 30 秒更新一次，可以接到 Uptime Kuma 之类的外部监控。
再配上通知渠道（`e5extend notify channel add`，见 [notifications.md](notifications.md)），出问题时会主动通知你。

## 为什么有的 API 一直是 403？

权限不足、账号没有对应的许可证或功能没开。接口返回 403 或 404 时，e5extend 会把它对这个账号**暂停 24 小时**，之后再试；
单独碰到这样的接口不算这一轮失败，也不影响其他接口；只有一轮里没有任何成功、而且账号能调用的接口**全部**都被拒绝（比如许可证或邮箱被收回）时，这一轮才算失败，连续 3 轮会触发自动暂停。概览、账号页和 `e5extend status` 会显示“N 个 API 暂停 24 小时”，`doctor` 的 `account.<名称>.apis` 检查里也有。`e5extend catalog list --account <名称>` 显示每个接口是否可用，
需要更多接口就在应用注册里授予更多只读权限并同意。

## 为什么邮件、日历、OneDrive 一直是 404？

账号没有对应的服务：没分配 Exchange Online 许可就没有邮箱（邮件、日历、联系人、待办都会 404），没有 OneDrive 许可则文件和 OneNote 会 404 / 400。
这和 403（权限不够）不同，加权限也没用。运行 `e5extend account test <名称> --recommend` 看哪些分类可用，
加 `--apply` 把可用的分类写进账号；桌面版在编辑账号的“API 分类”一步里有同样的检查。

## 为什么日志里有 throttled？

微软返回 429（或带 `Retry-After` 的 503）表示请求太快，要求放慢。e5extend 会按 `Retry-After`（秒数或 HTTP 日期）等待后重试同一个调用，
最多再试 2 次；要求等待超过 60 秒的，直接跳过这次调用。限流**不算失败**：不计入连续失败（自动暂停），也不计入 `failure_spike`。
概览和账号页显示“限流 N”。

## 新账号的邮件、OneDrive 一开始就 403 / 404

新建的用户或租户，邮箱和 OneDrive 往往要等账号**第一次登录 Microsoft 365** 才会开通：在 https://www.office.com 用这个账号登录一次，再分别打开 Outlook 和 OneDrive，最长可能要等 24 小时。
在此之前，邮件、日历、联系人、待办和 OneDrive 的接口都会返回 403 / 404，e5extend 会把它们暂停 24 小时。`doctor` 的 `account.<名称>.apis` 在“邮件或 OneDrive 一直被拒绝、从没成功过”时会提示这一点（应用身份账号改为提示“该用户可能没有邮箱或 OneDrive 许可”；持续超过 7 天仍没成功的，只作为信息显示，因为很可能是有意没有邮箱）；
开通之后运行 `e5extend account resume <名称>`（账号正常运行时也会清除这些 24 小时的接口暂停），桌面版的账号向导测试页也有同样的提醒。

## 账号被自动暂停了，会自己恢复吗？

会，但只限**因连续失败被自动暂停**的账号：暂停后 6 小时、再过 12 小时、之后每 24 小时，用一次轻量调用（`/me`，应用身份用 `/organization` 或最便宜的可用接口）试一下。
成功就自动恢复并发 `recovered` 告警。你手动暂停的账号（`account pause`）永远不会被自动恢复。需要你处理的状态（`invalid_grant`、需要重新登录等）仍然是
`needs_attention`，不会探测，修好之后会自己恢复，或者运行 `e5extend account resume <名称>`。

不想要自动暂停的话，在 `config.toml` 的 `[schedule]` 里写 `auto_pause = false`（桌面版：设置 → 高级设置 → 调用节奏）：连续失败的账号照常运行，不会暂停，也不探测；已经被自动暂停的账号会在配置重新加载（或服务重启）后恢复运行，你手动暂停的不受影响；`failure_spike`、`all_failing` 等告警照常发送。默认是 `true`。

## 开发者订阅标着 Legacy sandbox 怎么办？

微软在 [旧版订阅退役 FAQ](https://learn.microsoft.com/en-us/office/developer-program/legacy-subscription-retirement-faq)（2026 年 11 月发布）里说明，
开发者控制台（dashboard）上标着 **Legacy sandbox** 的订阅正在退役。那份 FAQ 没有给出一个统一的退役日期，要点是：

- **仍然符合资格的成员**：旧订阅会得到**最后一次 60 天的续期**（会发邮件，dashboard 显示到期日）。要继续开发，需要在到期前从 dashboard 新建订阅并自己搬走要保留的内容；新订阅是另一个租户，域名和租户 ID 都不同，数据不会自动迁移。
- **不再符合资格的成员**：旧订阅不会续期，到**当前订阅期结束**时到期。
- 到期后只读 30 天（只有管理员能登录恢复数据），期满即**永久删除**，删除后无法恢复。
- Legacy 订阅**不能再次续期，不能转换**成支持附加购买的订阅，权益也不能转给别的订阅。

请现在就到开发者控制台看你的订阅是不是 Legacy sandbox、到期日是哪天，并**备份**租户里需要保留的内容（应用注册、代码和配置、文件和邮件等，清单见上面的链接）。

这件事由微软决定，**没有任何工具能改变它**，包括 e5extend：它只发只读调用、报告到期日和状态，不能让订阅续期。以微软页面和你的 dashboard 为准。

## 续期失败了怎么办？

桌面版概览页右上角的“续期失败？”按钮会打开同样的清单。按顺序看：

1. **先确认是不是“旧版沙盒”（Legacy sandbox）订阅。** 在开发者控制面板上，这类订阅会标着“Legacy sandbox”。微软在退役它们，没有给出退役日期。
   仍符合资格的成员会得到最后一次 60 天的续期，并且应在它结束之前创建新的订阅；不符合资格的成员，订阅在当前期限结束时到期。
   到期后的 30 天里订阅是只读的（只有管理员能登录），之后会被永久删除，无法恢复，所以要提前备份数据。
   这是微软的政策，和本工具无关，本工具也无法改变它。以微软的说明为准：<https://learn.microsoft.com/en-us/office/developer-program/legacy-subscription-retirement-faq>。
2. **看开发者控制面板。** 登录 Microsoft 365 开发者计划的控制面板，确认订阅是否还在、什么时候到期、有没有被标成不符合条件。
3. **看概览页的“E5 订阅”卡片。** 它读取租户里的订阅状态和到期日（读不到时可以手动填到期日）；状态变化、续期成功和到期前 30、7、1 天都会通知。
4. **跑一次健康检查。** 桌面版的“健康”页，或 `e5extend doctor`：确认账号没有停在 `needs_attention`、调用没有大量失败、权限够用。
   账号本身出了问题时，续期当然也无从谈起。
5. **没有保证。** 这个工具只是让租户有规律的开发活动，是否续期由微软决定（见下一条）。

## 会不会保证续期？

不会。这个工具只是让租户有规律的、看起来自然的开发活动，是否续期由微软决定。

它能做的是**告诉你结果**：订阅什么时候到期、状态有没有变、有没有续上，到期前 30、7、1 天提醒，状态变化和续期也会通知（见
[看订阅什么时候到期](getting-started.md#看订阅什么时候到期)）。

## 概览页的“E5 订阅”卡片说读不到订阅信息

读订阅（`GET /directory/subscriptions`）需要 `Organization.Read.All`。应用身份的推荐权限里本来就有；委托身份（设备码、浏览器、账号密码）是新加的，
旧的应用注册没有。给账号正在用的应用注册补上它：桌面版点卡片上的“补齐权限”；命令行 `e5extend app setup --repair --account <账号>`（只补权限，不新建账号和 Secret）；或在 Entra 里手动添加后授予同意。然后点“全部刷新”或运行
`e5extend subscription`。登录的用户本身要能读目录，开发者租户的管理员满足。一时补不了就手动填写到期日，同样会提醒。

## 怎么升级？会不会自己偷偷升级？

不会偷偷升级。程序每天查一次有没有新版本，有的话在概览页和托盘菜单里提示（也可以走告警渠道），由你点“立即升级”或运行 `e5extend update install`。
升级前会验证发布签名和校验和。详见 [安装 → 升级](install.md#升级)。不想每天查：`config.toml` 里 `[update]` 写 `check = false`。

## 点“立即升级”提示没有签名，或只给了“打开发布页”

自动升级只安装**签名验证通过**的版本。出现这种提示的常见原因：这个版本发布时没有配置签名密钥；你用的是开发构建、Docker 镜像，或无法识别的安装方式；
Linux 命令行升级需要管理员权限时会给出一条 `sudo …` 命令让你自己运行。这些情况都可以到发布页手动下载新版本安装，安装包和以前一样用。

## 我的数据安全吗？

- 配置文件里不放 Client Secret、密码和令牌；它们和令牌缓存、通知渠道的令牌与地址一起放在 AES-256-GCM 加密的 vault 里。唯一的例外是旧版本的 `notify.webhook_url`：它可能还以明文留在 `config.toml` 里，`doctor` 会警告，`notify set-webhook` 会把它迁进 vault 并清掉。
- 只调用只读接口，不保存响应内容；日志里只有接口名、状态码和耗时。
- 主密钥丢失后 vault 无法读取，需要 `e5extend vault reset` 并重新输入密钥、重新登录。
